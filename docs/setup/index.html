Setup guide

About 15–20 minutes. Every command below has a copy button. Each step tells you what you should see before moving on.

  1. Create a Spotify Developer app

    Spotify Premium is required to create a developer app (this can't be checked automatically — it's a hard prerequisite). Go to the Spotify Developer dashboard and create an app.

    Use exactly this redirect URI — SpotiSort's local login server listens here:

    http://127.0.0.1:8888/callback

    Note the Client ID shown on the app page — you'll need it in step 3. No Client Secret is needed.

    You should see: your new app's dashboard page with a visible Client ID and the redirect URI listed under settings.

  2. Fork the repository

    Fork github.com/Vishnu-DRX/SpotiSort to your own GitHub account, then clone your fork locally.

    git clone https://github.com/<your-username>/SpotiSort.git
    You should see: a SpotiSort folder on your machine, and a fork under your own account on GitHub.

  3. Get your refresh token locally

    Install Python 3.12, then from inside your cloned fork:

    python -m pip install -r requirements.txt

    Copy .env.example to .env and put your Client ID from step 1 in it:

    SPOTIFY_CLIENT_ID=your-client-id-here

    Then run the one-time login:

    python -m src.spotify_client --setup

    This opens your browser to Spotify's own login screen, then captures the result on 127.0.0.1:8888. Nothing secret is printed to the terminal.

    You should see: a browser tab confirming login succeeded, and a new SPOTIFY_REFRESH_TOKEN line written into your local .env.

  4. Add the two Actions secrets

    SpotiSort's scheduled workflow needs SPOTIFY_CLIENT_ID and SPOTIFY_REFRESH_TOKEN as GitHub Actions secrets on your fork. Never paste these into this website — only into GitHub itself.

    Windows:

    powershell scripts/set_secrets.ps1

    macOS / Linux (values are piped in via stdin, never shown or logged):

    gh secret set SPOTIFY_CLIENT_ID --body "$SPOTIFY_CLIENT_ID"
gh secret set SPOTIFY_REFRESH_TOKEN --body "$SPOTIFY_REFRESH_TOKEN"
    You should see: both secrets listed under your fork's Settings → Secrets and variables → Actions (values are never shown again, only names).

  5. Allow Actions to write, and enable Pages

    In your fork: Settings → Actions → General → Workflow permissions, select Read and write permissions, and save. This lets the scheduled run commit its own logs back to your repo.

    Then: Settings → Pages, set source to Deploy from a branch, branch main, folder /docs.

    You should see: a Pages URL like https://<you>.github.io/SpotiSort/ serving your own copy of this site within a few minutes.

  6. Create your config

    Open Configure on your Pages site, build your rules, and select Save configuration. Put the downloaded config.yaml in your repo's root and commit it.

    You should see: config.yaml at the top level of your repo, matching what Configure previewed.

  7. First dry run

    On GitHub: Actions → Sync → Run workflow, leave dry run ticked, and run it. Then open your Dashboard and read the Overview and Inbox views.

    You should see: a green run in the Actions tab, and the dashboard showing what it would have moved — with nothing actually moved yet.

  8. Go live, later

    When the dry run looks right, live runs are still guarded: a newest N selector and a max-moves cap stop any single run from touching more than you expect.

    By default, committed run logs hide song titles (logging.include_track_names: false) — public logs carry counts and URIs only. Turn it on in Configure if you want your own logs to show titles, or open the log files locally in the dashboard to see titles regardless of this setting.

If something goes wrong

  • Login window doesn't open: re-run python -m src.spotify_client --setup; make sure nothing else is using port 8888.
  • Actions run fails immediately: check both secrets are set (Settings → Secrets and variables → Actions) and that Workflow permissions are Read and write.
  • Pages shows a 404: confirm the Pages source is main / /docs and wait a few minutes after enabling it.
  • Dashboard says data is stale: that's expected until a scheduled or manual run has completed and committed a new log.
  • Still stuck? Open an issue on the upstream repository.
